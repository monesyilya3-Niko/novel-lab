## 三、修了 3 个真实 Bug（原版有，实测暴露）

不是"看着像有问题"，是跑出来确实是错的：

**1. 章节检测判成 0 章（严重）**
- 位置：`webnovel-reverse-analysis/scripts/novel_analyzer.py`
- 原因：正则 `\n\s*第(...)章` 要求章节行**前面必须有换行符**，文件第一行的「第一章」直接被漏掉
- 实测：一个 3 章文本，原版输出 `Chapters: 0`
- 修复：改为 `(?:^|\n)\s*第(...)章`，兼容全角空格 U+3000 与「第1章 / 第一章 / 第 1 章」写法
- 修复后：稳定输出 3 章，均 220 字（min 198 / max 235）

**2. 角色提取漏人（严重）**
- 原因：动词表只有言说类（说/道/问/答…），「沈砚之握紧那枚玉」「沈砚之沉默了片刻」这类无对话标签的高频角色整段失踪
- 实测：原版只抓到 1 个角色，主角「沈砚之」完全不在列表里
- 修复：动词表扩到言说 + 表情 + 身体动作 + 心理四类（62 个），多音节词排在单音节词前避免截断
- 修复后：抓到「周执事 5 / 沈砚之 3」

**3. 输出目录不存在就崩**
- 位置：两个脚本的 `--out` / `--output`
- 原因：没有 `os.makedirs`，目录不存在直接 `FileNotFoundError`
- 修复：两个脚本都加了自动创建

## 四、实测证据：这套东西真的能区分文风

用我自己写的三段不同风格文本跑 `fingerprint_extract.py`，结果：

| 文件 | 均句长 | 短句率 | 对话率 | 逗号/百句 | 段长 | 连接词/百句 | 词汇多样性 |
|---|---|---|---|---|---|---|---|
| 风格A 短句快节奏 | **7.15** | 0.877 | 0.716 | **33.33** | 11.6 | 0.0 | 0.3731 |
| 风格B 长句重描写 | **22.95** | 0.590 | 0.615 | **151.28** | 38.9 | 10.26 | 0.3911 |
| 风格C 中间态 | 10.58 | 0.734 | 0.688 | 56.25 | 15.7 | 3.12 | 0.3708 |

关键对比：
- 均句长 **相差 3.2 倍**（7.15 vs 22.95）
- 逗号密度 **相差 4.5 倍**（33 vs 151）

这说明脚本量化的确实是"文笔手法"，不是随机噪声。你丢一本书进去，它会告诉你这个作者**平均一句话写几个字、多爱用逗号、对话占多少、段落切多碎**——这些就是可以拿来临摹的硬指标。

## 五、完整工作流：从"丢一本书"到"用它的手法写"

### 第 1 步：放书
把 txt/epub 丢进 `00_书库/<题材名>/`（按题材分目录）
- 支持 `.txt` `.tx` `.epub` `.epu`（含回收站恢复导致的 `.tx\ufffd` 畸形扩展名）
- 中文编码自动回退：gb18030 → gbk → utf-8

### 第 2 步：拆结构（用 webnovel-reverse-analysis）
```bash
python "C:/Users/monesy/.niko/skills/webnovel-reverse-analysis/scripts/novel_analyzer.py" \
  "00_书库/都市/某书.txt" --output "02_分析报告"
```
产出：章节数/字数分布/角色矩阵（主角+配角分层）/力量体系类型/文风 DNA（短句率、情绪词频、粗口密度、叙事模式）

### 第 3 步：提文笔指纹（用 novel-writing-pipeline）
```bash
python "C:/Users/monesy/.niko/skills/novel-writing-pipeline/scripts/fingerprint_extract.py" \
  --corpus "00_书库/都市" --out "01_指纹库/都市场指纹.json"
```
产出：句长分布、对话占比、连接词密度、标点节奏、POV 人称倾向、词汇多样性、段落长度、句首高频词

### 第 4 步：我读报告，写"手法清单"
统计数字本身不是手法。这一步是我做的：把数字翻译成可执行的写法规则，例如
> 均句长 8 字 → 单句只承载一个信息点，长句一律劈开；
> 逗号/百句 30 → 少用从句，用句号断气口；
> 对话率 0.7 → 用对话推进叙事，叙述段只做转场。

### 第 5 步：用这套手法写
- `novel-writing-pipeline` 的 9 角色流水线接手：总策划 → 世界观 → 角色 → 大纲 → 写手 → 场景对话 → 审计 → 节奏 → 润色
- 写作指纹注入写手 prompt，保证初稿就带这个声口
- 去 AI 味差分门禁：终稿 AI 味命中数必须严格小于改稿

### 第 6 步：自检
```bash
python "C:/Users/monesy/.niko/skills/novel-writing-pipeline/scripts/ai_taste_check.py" --draft "03_我的稿子/第01章.md"
```

## 六、版权边界（必须说清楚）

这套系统提取的是**统计特征**（句长、节奏、对话占比、标点密度），这些属于不受版权保护的写作技法层面。

**它不输出任何原文片段**——`fingerprint_extract.py` 的设计就是只算数字、不落文本，这也是我敢装它的原因之一。

但边界要守住：
- ✅ 可以学：句式节奏、结构手法、对话/叙述配比、视角习惯
- ❌ 不可以：复制具体表达、人物设定、情节桥段、世界观设定

简单说：**学手法，不抄内容。** 你拿去拆解自己买的正版书、公版经典都没问题；拆完照着手法写自己的故事，这是正当学习。

## 七、已知局限（诚实说）

1. **短文本不准**：677 字的样本里，主角判定会失真（我实测时「周执事」因动词命中更多被判为主角，而「沈砚之」才是真主角）。角色统计至少要几万字才可靠。
2. **句首词频在短样本全是 1**：需要长篇累积才有统计意义。
3. **角色提取仍靠正则**：简体中文人名没有形态标记，任何正则方案都会有噪声。长篇里靠频次能压住，短篇不行。
4. **`webnovel-reverse-analysis` 没写 LICENSE**：仓库里没有许可文件，严格说使用权不明确。我审计了代码本身是安全的，但如果你要基于它做二次分发，得先联系作者。
5. **重启才生效**：新装的 Skill 需要重启 niko 才会出现在技能列表里。
