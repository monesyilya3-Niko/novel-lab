# 增量 PRD — novel-lab GUI 全功能可视化工作台

> 产品经理：许清楚
> 文档类型：**增量 PRD**（基于 `docs/PRD_gui_book_analyzer.md` + `docs/DESIGN_gui_book_analyzer.md`，只描述「变更部分」）
> 上游现状：GUI 当前只接了「拆书」一条链路（导入 → 选章 → 拆书 → 断点续传），是 CLI 拆书流程的只读外壳。
> 本次目标：把 GUI 从「拆书查看器」升级为「novel-lab 全功能可视化工作台」，暴露引擎全部 20 个子命令 + 写作辅助 + 数据管理 + 丰富拆书主链路 + 数据可视化。

---

## 0. 变更摘要（一句话）

**novel-lab GUI 的定位从「拆书查看器（1/20 子命令）」升级为「全功能可视化工作台（20/20 子命令 + 写作 + 数据管理 + 可视化）」**，分三阶段交付，每阶段独立可验收。

---

## 1. 产品目标（定位变更）

### 1.1 旧定位 → 新定位

| 维度 | 旧（PRD_gui_book_analyzer） | 新（本次） |
|---|---|---|
| 产品定位 | CLI 拆书流程的「可视化外壳」 | novel-lab **全功能可视化工作台** |
| 能力覆盖 | 仅「拆书」1 条链路（20 子命令中的 1 个） | 引擎全部 20 子命令 + 写作辅助 + 数据管理 |
| 核心用户 | 拆书作者 | 拆书作者 + 写作者（用资产产出新章节）+ 编辑/校对（批量质检） |
| 视觉 | 无数据可视化 | 精致美观 + 数据可视化「两者都要」 |
| 交付方式 | 一次性 | 分阶段，每阶段可验收 |

### 1.2 三个升级目标（正交）

| # | 目标 | 说明 | 可衡量标准 |
|---|---|---|---|
| G1 | **全能力暴露** | 引擎 20 个子命令在 GUI 中都有对应入口，用户无需碰 CLI | 20 子命令全部映射到界面，且核心链路可端到端走通 |
| G2 | **从「拆」到「写」闭环** | 拆书产出的资产（voice-card/craft-card/structure/commercial）可继续用于注入 → 写作 → 打分，形成创作闭环 | 用户能在 GUI 内完成「导入书 → 拆 → 蒸馏/聚合 → 注入 → 写新章 → 打分」完整流程 |
| G3 | **精致可视化** | 关键数据（评分、进度、质检分布、资产结构、报告）以图表呈现，界面美观统一 | 核心面板均有对应可视化元素（雷达图/进度环/对比图/报告渲染），视觉风格统一 |

> 旧 PRD 的 G1/G2/G3（降门槛 / 可视化长文本 / 可靠续传）作为**基础能力保持不变**，本次增量在其之上叠加，不推翻。

## 3. 分阶段规划

### 阶段总览

| 阶段 | 主题 | 模块范围 | 核心验收 |
|---|---|---|---|
| **阶段一** | 拆书结果可视化 + 数据管理打底 | M1（拆书主链路增强）+ M0 首页 + M4 资产库（只读浏览） | 拆书产出以可视化呈现；数据可管理；首页可概览 |
| **阶段二** | 写作闭环 | M2 写作 + M3 质检 | 资产 → 注入 → 写作 → 打分端到端走通 |
| **阶段三** | 系统与高级能力 | M5 系统与合规 + M1 高级（蒸馏/聚合/批量）+ M4 资产库（写入/转换） | 全能力暴露，合规/校验/模型配置可用 |

### 阶段一（打底，本次最高优先级）

**范围**：M1 拆书主链路增强 + M0 首页 + M4 资产库（只读）。

**为什么阶段一必须是「拆书结果可视化 + 数据管理」**：
1. 用户核心反馈「功能太少」的根源是：现有 GUI 拆完书后**只能看原始 JSON，看不到结构化/可视化结果**。
2. 拆书主链路已有后端基础（engine_adapter / services / router 已接 pipeline），增量成本最低、见效最快。
3. 数据管理是后续所有模块（写作/质检/资产库）的地基，必须先有统一的资产索引与浏览能力。

**阶段一模块清单**：

| 模块 | 子命令 | 阶段一范围 |
|---|---|---|
| M1 分析 | 拆书 | 保留现有拆书链路，**新增结果可视化**（资产卡渲染 + 章节打分对比 + 报告渲染） |
| M1 分析 | 分析 | 一键「拆书 + 报告 + 笔法报告」串联入口 |
| M1 分析 | 报告 / 笔法报告 | 报告 Markdown 渲染（读 reports/*.md） |
| M0 首页 | 状态 | 项目概览仪表盘（资产数/报告数/模型状态） |
| M4 资产库 | （只读） | 浏览 assets/*.json 的资产清单，暂不做导入/转换 |

**阶段一验收标准**：
- 拆书完成后，结果面板可查看结构卡/人物卡/文风卡/商业卡的结构化渲染（非裸 JSON）。
- 章节一致性/质量评分以雷达图或柱状对比图呈现。
- 报告面板可渲染 Markdown 报告（拆书报告 + 笔法分析）。
- 首页概览可展示「已拆 N 本 / 题材包 N 份 / 报告 N 份 / 模型状态」。

### 阶段二（写作闭环）

**范围**：M2 写作 + M3 质检。

**依赖**：阶段一的资产索引与数据管理（写作需读取拆书产出的 voice-card / craft-card / structure / commercial）。

**阶段二模块清单**：

| 模块 | 子命令 | 阶段二范围 |
|---|---|---|
| M2 写作 | 注入 | 选择 voice-card（+结构/商业/题材包/文风卡/craft/蒸馏）→ 生成写作 prompt，界面可预览 |
| M2 写作 | 写作 | 填「章节号 + 任务要点 + 目标分 + 字数」→ 生成章节（含改写循环进度） |
| M2 写作 | 打分 | 上传/选择章节 → 一致性打分可视化 |
| M2 写作 | 组装 | 无模型模式：pass1-5 JSON → 入库资产 |
| M3 质检 | 检查 | 单章质量 + 一致性双维度检测 |
| M3 质检 | 质检 | 全书内容质检（重复/连贯/凑字数/AI味） |
| M3 质检 | qc | 四层十二维统一质检 |

**阶段二验收标准**：
- 用户能在 GUI 内完成「选资产 → 注入生成 prompt → 写作 → 打分」闭环。
- 写作的改写循环进度可实时展示（目标分 90 的迭代过程）。
- 质检结果以问题分布图（severity 堆叠）+ 问题列表呈现。

### 阶段三（系统与高级能力）

**范围**：M5 系统与合规 + M1 高级（蒸馏/聚合/批量）+ M4 资产库（写入/转换）。

**依赖**：阶段一 + 阶段二全部就绪。

**阶段三模块清单**：

| 模块 | 子命令 | 阶段三范围 |
|---|---|---|
| M5 系统 | 模型 | 模型配置界面（11 预设 + 路由 + 连通性测试） |
| M5 系统 | 校验 | 资产 schema 校验（选 kind） |
| M5 系统 | 合规 | 版权合规扫描（资产 + 原文） |
| M5 系统 | state-track | 长文本状态追踪（show/apply/validate/context） |
| M1 分析 | 批量 | 目录多本 TXT 批量拆书（队列） |
| M1 分析 | 聚合 | ≥3 本同题材 → genre-pack |
| M1 分析 | 蒸馏 | ≥2 本同题材 → 四类蒸馏资产 |
| M4 资产库 | import-genre-prose-cards | 批量移植题材文风卡 |
| M4 资产库 | convert-genre-card | 散文卡 → genre-pack 规则包 |

**阶段三验收标准**：
- 模型配置界面可读写 `config/models.json`，可测试连通性。
- 合规/校验结果可视化呈现（含风险分级）。
- 批量拆书队列可见、可中断续跑。
- 资产库支持导入与转换（写入能力）。

## 5. UI 规划

### 5.1 导航结构变更（左侧栏）

旧导航（7 项）→ 新导航（6 个工作台，按业务域重组）：

```
[首页概览]          ← M0：项目仪表盘 + 数据管理入口（新增）
[分析工作台]        ← M1：拆书主链路 + 报告 + （阶段三：批量/聚合/蒸馏）
[写作工作台]        ← M2：注入 → 写作 → 打分 → 组装（新增）
[质检工作台]        ← M3：检查 / 质检 / qc（新增）
[资产库]            ← M4：资产浏览 + 导入/转换（阶段一：只读）
[系统与合规]        ← M5：模型 / 校验 / 合规 / state-track（新增）
[设置]              ← 全局设置（批次参数、端口、主题）
```

> 旧 PRD 的「导入书籍 / 章节列表 / 内容阅读器 / 分析进度 / 分析结果 / 模型配置」合并进「分析工作台」内作为子视图，保留现有拆书能力不丢失。

### 5.2 各模块界面要点 + 数据可视化元素

| 模块 | 界面要点 | 关键交互 | 数据可视化元素 |
|---|---|---|---|
| **M0 首页** | 顶部 KPI 卡片（已拆 N 本 / 题材包 N 份 / 报告 N 份 / 模型状态），下方数据管理快捷入口 | 点击 KPI 跳转到对应模块 | 数字卡片 + 状态点（模型绿/灰） |

### 5.3 视觉与数据可视化规范（新增）

- **整体风格**：延续 MUI + Tailwind，统一色板（主色 + 状态色：成功绿/处理中蓝/失败红/跳过灰黄），精致卡片 + 圆角 + 阴影层级。
- **图表库**：引入前端图表库（候选：Recharts / ECharts，前端层不受「纯标准库」铁律约束，见旧 PRD §5/§6 结论）。
- **必做可视化元素（P0）**：
  1. 拆书进度环（整本书完成率）
  2. 章节打分对比图（雷达图或柱状，各章质量/一致性分）
  3. 质检 severity 分布图
  4. 报告 Markdown 渲染
- **P1 可视化元素**：改写循环进度环、十二维质检雷达图、题材包结构树。
