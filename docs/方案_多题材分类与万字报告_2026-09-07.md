# novel-lab 多题材分类 + 1万字报告 落地设计方案

> 版本 v1.0 · 2026-09-07 · 状态:待主理人(monesy)审阅确认后实施

## 一、背景与三条硬性要求

用户提出的三条铁律,作为本方案的顶层约束:

1. **多题材包分类隔离**:后续会有多个题材包,写作技巧必须按题材分类,不能混为一谈。
2. **每本书 ≥1 万字分析报告**(硬门槛)。
3. (本方案在此之外,补齐工程落地机制,确保前两条不被口头化、不退化)

---

## 二、现状诊断(实测确认)

### 2.1 题材隔离:数据已隐式隔离,但缺"显式拦截"

| 现状 | 问题 |
|------|------|
| craft-card `meta.genre` 已标 `campus-redemption` | 无校验,错误题材值不会报错 |
| `pass5_aggregate.py` 的 `collect_books` 已按 genre 过滤(第 51 行 `if vc.get("meta", {}).get("genre") != genre: continue`) | **静默跳过**,而非报错——混入错误题材的书会被悄悄忽略,用户无感知 |
| `trope-library.json` 的 `contributing_books` 混 3 本不同书 | 桥段库无"题材归属"标记,跨题材检索无法过滤 |
| genre-pack schema 的 `source_books` 无 genre 一致性校验 | 理论上可混题材 |

**结论**:需要把"静默跳过"升级为"显式断言 + 报错",并给桥段库加题材作用域。

### 2.2 报告字数:严重不达标

| 报告 | 当前字数 | 距 1 万字 |
|------|---------|-----------|
| 6 份报告平均 | ~3000 字符 | 缺 ~7000 |

**根因**:`report_craft.py` 的 `_technique_block` 只平铺 4 段(name/description/effect/skeleton/anti_pattern),是"资产字段搬运",非"深度分析"。撑不起 1 万字。

---

## 三、方案设计

### 3.1 硬性要求落盘:新增 `PROJECT_LAW.md`(项目宪法)

在项目根目录新增 `PROJECT_LAW.md`,写入三条铁律 + 各条的执行机制。作为所有后续开发、所有 team 成员、所有拆书任务的"宪法",任何违反即视为 bug。

**内容骨架**:
```markdown
# novel-lab 项目规约(硬性要求)

## 铁律一:写作技巧严格按题材分类隔离
- 每个题材包(genre-pack)独立,技法不得跨题材混用
- 聚合题材包时,source_books 的 genre 必须全部一致,不一致直接报错(非静默跳过)
- 桥段库(trope-library)必须标注 genre_scope(通用 / 某题材专属)

## 铁律二:每本书拆解必须产出 ≥1 万字分析报告
- 拆书报告 + 笔法分析 合计字数 ≥ 10000 字符(硬门槛)
- 报告生成后自动校验,不足则报错阻断,不产出"半成品"报告

## 铁律三:纯标准库、零第三方依赖(既有约束,重申)
```

### 3.2 题材隔离机制(3 处改动)

#### ① `pass5_aggregate.py` — 静默跳过 → 显式断言

在 `collect_books` 中,把 `continue`(静默跳过)改为:
- **同题材书**:正常收集
- **混入不同 genre 的书**:收集到 `mismatch` 列表,聚合前**硬报错**,打印"书名 X 的 genre=Y,与目标题材 Z 不符,已阻断聚合",并 `sys.exit(1)`

同时保留 `--books` 显式指定书单时同样校验。

#### ② `validate.py` — craft-card genre 枚举校验

新增:craft-card 的 `meta.genre` 必须非空,且属于已知题材枚举(维护一个 `KNOWN_GENRES` 集合,当前含 `campus-redemption`,后续扩题材时在集合内追加)。非法 genre → 报 warning(不阻断拆书,但阻断聚合)。

#### ③ `trope-library.schema.json` + `trope-library.json` — 加 `genre_scope`

- schema:每个 trope 增加 `genre_scope` 字段,`enum: ["universal", "campus-redemption", ...]`(universal=跨题材通用桥段,具体题材 id=题材专属桥段)
- 现有 8 个 trope 回填 `genre_scope`(按是否含题材专属元素判断,预计多数为 universal,少数 campus-redemption 专属)
- `retrieve.py` 检索桥段时,按目标题材过滤:`genre_scope == "universal"` 或 `genre_scope == 目标题材`

### 3.3 报告深度化(自动深度展开,撑到 1 万字)

#### 新增 `scripts/deep_analyze.py`(技法二次深度分析)

在拆书 Pass5 产出 craft-card 之后、生成报告之前,插入一个"技法深度展开"环节。每条技法从 4 段扩展到 **10 段**:

| # | 段落 | 内容 | 说明 |
|---|------|------|------|
| 1 | 原文现象 | 技法在原文中的具体表现 | 已有(description) |
| 2 | 技巧拆解 | 拆成可复制的操作单元 | 已有(skeleton) |
| 3 | **读者心理机制** | 为什么这招对读者有效(爽点/张力/共鸣的心理学解释) | **新增** |
| 4 | **执行步骤** | 分步可落地的操作指南(1.2.3.) | **新增** |
| 5 | 反例对比 | 不这么写的后果 | 已有(anti_pattern) |
| 6 | **适用场景** | 什么时候该用(题材/节奏/位置) | **新增** |
| 7 | **使用边界** | 什么时候不该用、用多了的副作用 | **新增** |
| 8 | **强度控制** | 该技法的力度调节(强/弱两档) | **新增** |
| 9 | **组合套路** | 与其他技法的常见搭配 | **新增** |
| 10 | **迁移清单** | 换成自己的书该怎么套用 | **新增** |

**实现方式**(纯标准库,零依赖):
- 深度展开的 6 个新增段落,由 LLM 在 Pass5 阶段一次性生成(扩展 Pass5 的 prompt,让模型对每条技法补 6 段深度分析),而非本地规则硬凑——本地规则拼不出"读者心理机制"这种内容。
- `deep_analyze.py` 作为**质量校验 + 组装器**:校验每条技法是否 10 段齐全、深度字段是否为空,缺则标记;把深度分析写入 craft-card 的扩展字段(如 `technique.deep_analysis`)。

#### `report_craft.py` + `report.py` — 渲染深度字段

报告渲染器读取 `deep_analysis` 扩展字段,把 10 段全部渲染进报告,而非现在的 4 段。

#### 硬校验:`MIN_REPORT_CHARS = 10000`

在 `report.py` 和 `report_craft.py` 生成报告后:
```python
MIN_REPORT_CHARS = 10000
if len(report) < MIN_REPORT_CHARS:
    print(f"⚠️ 报告字数 {len(report)} < 硬门槛 {MIN_REPORT_CHARS},请补充深度分析")
    sys.exit(1)  # 阻断交付,不倒逼出半成品
```
同时把"拆书报告 + 笔法分析 合计 ≥1 万字"的判定也加入 `pipeline.py` 的收尾检查。

### 3.4 借鉴 `ADANIE/novel-writeskills` 的分层结构(为多题材铺路)

采用其"通用能力 + 题材专属"双层组织,落地到 novel-lab 的资产目录:

```
assets/
├── universal/            # 跨题材通用技法(新增目录)
│   └── trope-library.json   # 通用桥段(genre_scope=universal)
├── campus-redemption/    # 题材专属(现有资产迁入)
│   ├── *-craft-card.json
│   ├── *-voice-card.json
│   └── campus-redemption-genre-pack.json
└── <未来题材>/           # 每新增一个题材,新建一个目录
```

> 注:目录迁移是较大动作,可拆为独立子任务(P3),不在本期一次性做完,避免动到 98 个测试的资产路径引用。

## 五、风险与权衡

1. **报告深度化依赖 LLM 二次生成**:6 段新增深度内容(心理机制/执行步骤/边界等)无法靠本地规则产出,需扩展 Pass5 的 LLM prompt。代价是拆书时 LLM 调用 token 增加;收益是报告真正达到交付质量。**若你希望零 LLM 增量,则深度字段只能留空占位,报告仍达不到 1 万字**——需明确取舍。
2. **1 万字门槛的"字符 vs 汉字"口径**:`len(report)` 统计的是字符数(含标点、换行、Markdown 符号)。建议明确口径为"纯正文汉字数 ≥ 10000",更严格;或用字符数口径更宽松。待确认。
3. **目录迁移(3.4)风险**:会改资产路径,牵连 98 个测试里的路径引用,需谨慎分步。故列为可选 P3,建议在 T01-T07 稳定后再做。
