## 二、整体结构解析（已核实）

### 2.1 定位

**一句话**：把优秀小说拆成可复用的结构化资产（声线卡/笔法卡/结构观测/商业观测/题材包），再用这些资产驱动 AI 创作。

### 2.2 架构分层（与代码一致）

```
┌─ 拆书层 ──────────────────────────────────────────────┐
│ pipeline.py  TXT → 采样(27章) → 量化 → 五遍扫描 → 归一化 → 资产 │
│   ├ sampler.py   分层采样（开篇10+中段15+卷末2）        │
│   ├ metrics.py   量化（句长/对话占比/TTR/五感）          │
│   ├ normalize.py 中文键→schema 英文键（模糊匹配4种格式）  │
│   ├ validate.py  6类 schema 校验                        │
│   └ compliance.py 版权合规（12字原文匹配→REJECT）        │
├─ 聚合层 ──────────────────────────────────────────────┤
│ pass5_aggregate.py  ≥3本同题材 → genre-pack 题材包      │
├─ 写作层 ──────────────────────────────────────────────┤
│ inject.py    资产 → 写作 system prompt（6~10节）        │
│ write.py     生成 + 三维度改写循环                       │
│ consistency.py  五维一致性打分                          │
│ chapter_check.py 12维100分制章节自检                    │
│ book_quality.py  6类全书质检                            │
├─ 指纹拆书（副线）─────────────────────────────────────┤
│ novel_analyzer.py / fingerprint_extract.py / ai_taste_check.py │
├─ 产出层 ──────────────────────────────────────────────┤
│ report.py / report_craft.py  →  可交付 Markdown 报告     │
│ novel.py   CLI 统一入口（15 子命令）                     │
└────────────────────────────────────────────────────────┘
```

### 2.3 关键实现逻辑

- **无外部模型模式（当前态）**：`llm_client.any_model_configured()` 检测不到模型时，`pipeline.py` 与 `write.py` 会**优雅降级**——完成采样+量化后生成 `AI接管任务.md`，由 WorkBuddy 会话内 AI 直接读文本完成五遍扫描/写作，走 `normalize → validate → compliance` 入库。**实测确认该降级路径真实生效**。
- **组装闭环**：`assemble.py`（2026-09-01 新增）把 AI 产出的 pass1-5 中文键 JSON 一键组装成 4 类资产，兼容 pass5 的 4 种输出格式，补上了"AI 产出→入库"的最后一公里。

4. **非 git 仓库**：`.gitignore` 已精心配置（密钥/版权原文/缓存都排除了），但项目**没有 `git init`**。意味着资产、脚本、prompt 无版本历史，误删/误改不可回滚。这与项目"资产可版本化"的核心理念相悖。
5. **pass1-5 端到端从未实战验证**：文档 FAQ 已诚实声明——"采样/量化/降级/校验/合规已实测，但 pass1-5 由 AI 产出→入库的端到端流程尚未在真实新书跑过完整一本，第一本新书即首次实战"。`corpus/raw/` 下 3 本书的 pass JSON 是历史产出，非走新 `assemble.py` 流程产出的。

## 五、存在的隐患

| 隐患 | 严重度 | 说明 |
|---|---|---|
| 写作链路从未实战 | 🔴 高 | write.py/consistency/chapter_check 单元功能存在，但"注入→写作→三维度改写→入库"全流程没有真实跑过一本新书，首次实战可能暴露 prompt 注入与改写循环的衔接问题 |
| 无版本控制 | 🟠 中 | 资产与脚本无 git 历史，不可回滚，与"资产可版本化"理念冲突 |
| 外部模型恢复链路未验证 | 🟠 中 | llm_client.py 代码保留但当前无配置，`model_config.py add` 恢复外部模型的路径自删除后未再实测，未来恢复时可能踩密钥/协议坑 |
